# Tx-Pool Security and Regression Ledger

This ledger is the security gate for the production tx-pool pipeline. It is
derived from the historical review notes, validated reports and reorg/template
regressions. The six-state two-authority target is implemented and specified in
[`ARCHITECTURE.md`](ARCHITECTURE.md); P5–P7 acceptance remains tracked in
[`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md). Entries below remain
mandatory behavior evidence; their machine-readable I1-I12 to
F1-F8/T1-T13 bridge is
[`architecture-contract.json`](architecture-contract.json).

Status meanings:

- **Covered**: a focused automated regression exists.
- **Guarded by current boundary**: the vulnerable legacy mechanism is gone and
  the current source boundary plus broader invariant tests enforce the
  property, but the exact hostile/failure example does not yet have a focused
  current-architecture regression. These rows are explicit S3 obligations and
  cannot remain in this state at final acceptance.
- **Covered; O5 deferred**: correctness and bounded-complexity evidence is
  complete; only measured performance calibration remains in the explicitly
  deferred benchmark gate.
- **Partial**: behavior is covered indirectly or its attack/performance stress
  remains incomplete.
- **Open**: no sufficient automated regression exists yet.
- **Accepted**: intentional compatibility behavior, with its resource/safety
  boundary stated explicitly.
- **Superseded**: the vulnerable mechanism was deleted; the security property
  is enforced and tested at its kernel/pool/effect-journal replacement boundary.

## Architectural invariants

| ID | Invariant | Required evidence |
|---|---|---|
| I1 | One lifecycle owner | Before acceptance, a transaction payload has exactly one full-hash owner, one typed location and one globally non-reused version in PrePoolKernel; dependency/conflict/queue/deadline structures are derived ID indexes. Acceptance consumes that record and transfers sole authority to TxPool, which is never shadowed. |
| I2 | Authoritative commit | Only the transaction sequenced by the existing TxPool write guard can accept/reject RBF or mutate pool membership; coordinator finalization completes before that guard opens. |
| I3 | Mutation-free rejection | RBF, capacity, liveness, ancestry and identity failures are decided by one immutable plan before accepted membership changes; rejected candidates therefore require no restoration. |
| I4 | No silent loss | Every admitted transaction reaches pool, wait state, explicit rejection, or retryable internal failure. |
| I5 | Bounded untrusted state | Global and per-peer count/byte/active-work limits continuously cover queued, active and parked payloads, conservative dependency/conflict/ticket/deadline metadata, and every queued/active terminal payload retained by the statically partitioned effect journal. |
| I6 | Event-driven dependencies | Parent commit/failure wakes or reclassifies children; no child relies solely on polling or expiry. |
| I7 | Reliable chain transitions | Reorg deltas are ordered, tip-checked, retained until success, and never best-effort. |
| I8 | Stable-state effects | Immutable callbacks, relay events, metrics, and notifications pass an exact static-region predicate, are appended to one sequence under the journal's innermost lock before authority guards open, then run after internal ownership is stable and outside locks. |
| I9 | Deterministic conflict scheduling | Fee preference may order work, but speculative state cannot create a terminal verdict or fee-floor bypass. |
| I10 | Pool graph integrity | Full-hash entries are authoritative; links, outpoint/status/sort indexes, accounting and ancestor/descendant weights change only through a bounded total Apply or an explicit administrative transition. |
| I11 | Template liveness | Pool status, proposal selection, uncles, byte accounting, and template revisions cannot strand a valid transaction. |
| I12 | Performance non-regression | The target passes the checkpoint A/B throughput, latency, CPU, allocation, RSS, reorg, and template gates. |

## Final-audit risks

| ID | State | Evidence / remaining resolution |
|---|---|---|
| O1 | Resolved | Stage queues use owner-head heaps and global capacity/conflict victims use derived ordered indexes. Saturated-prefix/strong-suffix probes bound inspected heads/keys independently of transaction count; the audit rebuilds both indexes exactly. |
| O2 | Resolved | Normal accepted/reorg effects use startup-validated static regions over configured bounds. Generation-wide reconciliation is a separate prebuilt, replaceable constant-size `GenerationReset` register: it owns no FIFO budget, coalesces to the latest sequence and remains publishable when every region is full. A chain Apply never waits behind detailed callbacks/relay; saturated critical detail is discarded in favor of that reset authority. |
| O4 | Resolved semantically | Conflict recovery still holds `TxPool` across the single-owner cache→coordinator handoff, but coordinator admission no longer scans the live store. The fixed 32-item slice and indexed planning bound lock work; measured lock latency remains part of O5 rather than an unbounded attack path. |
| O5 | Open by instruction | Run clean repeated quick A/B near production readiness only after explicit instruction; medium/full remain explicit-only. Unit timing is not a performance verdict. |
| O6 | Accepted residual | `TxSelector` stops after 4,000 consecutive non-fitting packages. This bounds adversarial template CPU but permits a crafted high-score non-fitting prefix to cause bounded underfill/delay of later fitting transactions. Removing the cap reopens O(pool) work; resolve only with a resumable cursor or fit-aware index plus packing-quality and CPU/RSS A/B evidence. |
| O7 | Resolved | Clear and over-bound chain recovery exchange one sealed pre-pool/ephemeral generation at the existing `TxPool -> PrePoolKernel -> EffectJournal` boundary. Retired population is destroyed after authority guards open, clocks live in the stable kernel shell, and there is no defect restart/quarantine/cooling protocol. `chain_generation_reset_retires_old_generation_outside_the_lock`, the ABA test and over-bound reorg regression cover the ordinary administrative distinction. |
| O8 | Resolved | `review-behaviors.json` is the normalized executable-evidence registry and generates the reviewer appendix; the sectioned inventory freezes all 228 internal-feature unit names and the complete 149-spec managed process universe, with 13 focused integration anchors. CI checks guide drift, test seams, I1-I12 anchors and registered process impact. Process specs run only through `make integration CKB_TEST_ARGS='...'`. |
| O9 | Resolved | P1 deleted the split coordinator/runtime/conflict-cache ownership and P2 deleted accepted rollback/cell-ref escape. One concrete `PrePoolKernel` owns six locations; Recovery is source metadata and full-hash PoolMap membership is the accepted authority. Payload-free fair queues, canonical causal keys, Wait epochs, Ready indexes and accepted projections are derived. Independent rebuild/reference models retain proof without deleted undo/commit/defect states. |
| O10 | Operations debt | Kernel residency, typed rejection classes, worker failure and effect-journal region usage are logged/test-visible but do not yet have dedicated production metrics. Add counters/gauges before claiming automated operational SLO detection; absence of metrics does not weaken the static safety boundary. |
| O11 | Resolved; O5 measurement remains | `EntryState::location()` returns the copy-only six-state `PrePoolLocation`; dependency sets are primary facts and external views remain read-only. Expected chain/admin reset swaps a sealed generation, while impossible contradictions fail fast and skip persistence rather than sharing a repair mechanism. Final allocation/latency measurement stays under O5. |
| O12 | Resolved | Mutation-coupled PoolMap/kernel effects use `try_apply`/`try_apply_bounded`, so capacity failure precedes Apply and stable append shares the innermost critical section. Standalone async append is limited to outcomes with no paired lifecycle mutation. No authoritative unwind-repair path remains. |
| O13 | Accepted compatibility residual | The current persistence writer orders by the verified `PoolMap` graph, including expanded dep-group members. An older or hand-authored v1 file can still place a child before an expanded member because the file stores raw transactions only; the serial loader may reject that child before the member is replayed. Fixing historical files requires a versioned batch-resolve/retry loader rather than another raw ordering heuristic. This can lose only local mempool contents across restart, not accepted chain state. |
| O14 | Operations/performance debt | Troubleshooting RPC rank/ancestor detail performs bounded-but-O(pool/graph) work under a pool read guard, shutdown persistence clones/sorts the accepted pool, and each operator-configured assembler notify endpoint/script owns one timeout-bounded task per notification. These are not remote admission hot paths or new owners, but RPC rate limits, endpoint-count validation and O5 latency/RSS measurements are required before claiming operational isolation under hostile RPC/configuration load. Adding mutable rank or notification caches would create a second projection and is not justified without measurements. |
| O15 | Accepted precision residual | Raw-only conflict history cannot know dep-group expansion, header context, or maturity until it resolves again. Accepted/verified victims enrich all expanded outpoint wake edges, and dynamic coordinator dependency extension prevents premature raw handoff from losing ownership, so no integrity or liveness counterexample remains for outpoint parents. A raw record may still perform an unnecessary resolve or receive a contextual terminal outcome; carrying verified payload through every terminal API or adding contextual wake protocols is deferred until a concrete production liveness case exists. |

## Migration and performance gates

1. No split lifecycle owner may be reintroduced. A new store must declare
   whether it is authoritative, historical, an ID-only index, or best-effort.
2. Every new lifecycle transition requires a coordinator/invariant test and a
   production-path regression at the affected authority boundary.
3. Performance runs are deferred until the correctness architecture and
   production ownership cutovers are nearly complete. At final acceptance run
   focused quick A/B first; medium/full remain explicit-only, and an
   interrupted or incomplete run has no verdict.
4. Throughput geometric mean must not decrease. A negative per-scenario median
   is a rerun condition; a repeated or statistically significant negative result
   blocks the phase.
5. Workload, sample count, safety checks, and timeouts cannot be weakened to
   pass the gate.
6. O1, O2, and O4 are resolved by indexed planning and formula-bound effects.
   O5 must pass under explicit benchmark instruction before declaring production
   readiness; no correctness result substitutes for that verdict.
